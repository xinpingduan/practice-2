# 员工管理与智能排班系统：面试讲解

## 一分钟介绍

这是一个基于 Flask、MySQL 和原生 JavaScript 的员工管理系统。系统覆盖员工入职、档案维护、任务流转、部门审批、智能排班、调班请假申请、通知审计，以及带会话记忆的 AI 助手。我的重点是把业务状态流转、权限边界和数据库一致性做清楚，而不是只完成页面展示。

## 技术架构

```text
浏览器（HTML / CSS / JavaScript）
        |
        v
Flask API（鉴权、校验、路由、响应）
        |
        +--> 领域服务（员工、排班规则、通知、AI）
        |
        +--> MySQL（业务数据、审计日志、AI 会话）
        |
        +--> 大模型 API（AI 助手的回答生成）
```

## 可重点讲的功能

### 1. 权限与流程控制

- 角色包括普通员工、部门经理、人事和超级管理员。
- 入职、离职、排班审批按照状态机推进，接口会校验当前状态和当前操作者权限。
- 登录失败次数和锁定时间保存到数据库，避免只依赖内存状态。

### 2. 排班与并发一致性

- 班表带 `version` 字段，审批或变更时校验版本，避免旧页面覆盖新数据。
- 特殊申请审批中使用事务和 `FOR UPDATE` 锁定申请及关联排班记录。
- 排班规则检查连续工作天数、每日/月度工时、最小休息间隔和岗位最低人数。

### 3. AI 助手与记忆

- 服务器从可信数据库会话中恢复上下文，浏览器不能伪造历史消息。
- 支持完整、窗口、Token、摘要四种记忆模式。
- 会话事实记忆单独保存用户主动声明的称呼；原始聊天记录仍遵从所选记忆策略。
- AI 数据查询采用白名单表、只读 SQL 和按角色追加范围条件，避免越权查询。

### 4. 可维护性改造

- 使用 `services` 承接领域逻辑，`utils/mysql_storage.py` 统一数据库连接与基础查询。
- `database/bootstrap.py` 承接开发环境演示账号初始化，降低 `app.py` 的职责。
- `migrate.py` 使用 MySQL advisory lock 串行执行结构迁移。

## 面试追问与回答要点

**为什么 AI 历史不从前端传？**

前端提交的历史可以被篡改，因此服务端根据登录用户和会话 ID 从数据库加载消息，保证上下文可信。

**如何避免 AI 查询数据库越权？**

只允许单条 `SELECT`，限制可查询表和字段；部门经理查询时在 SQL 外层追加部门条件，敏感字段例如密码永不返回。

**如何处理高并发审批？**

对涉及状态判断和多表更新的流程使用事务和行锁，同时通过版本号防止并发覆盖。

**后续如何继续演进？**

将 `app.py` 的路由按认证、员工、排班、审批、AI 拆分为 Blueprint 模块；将散落 SQL 继续下沉到 repository 层，并为迁移引入顺序编号的 SQL 文件。
