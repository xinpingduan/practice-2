# 数据库结构说明

数据库为 MySQL，默认使用 InnoDB 与 `utf8mb4`。初始化与兼容迁移入口为 `backend/migrate.py`，它使用 MySQL advisory lock，防止多个进程并发修改表结构。

## 核心实体

| 表 | 用途 | 关键关联 |
| --- | --- | --- |
| `employees` | 员工账号、角色、部门、在职状态 | 多数业务表通过 `employee_id` 关联 |
| `departments` | 部门树与部门说明 | `parent_id` 自关联 |
| `employee_tasks` | 员工待办、入职交接、离职流程 | 关联 `employees` |
| `onboarding_records` | 入职办理队列 | 关联 `employees` |
| `employee_records` | 已归档员工档案 | 与员工一对一 |
| `admin_todos` | 超级管理员终审事项 | 关联任务和员工 |

## 排班领域

| 表 | 用途 | 关键关联 |
| --- | --- | --- |
| `shift_types` | 班次定义、起止时间和工时 | 被排班分配引用 |
| `work_calendar` | 工作日/休息日配置 | 以日期为主键 |
| `scheduling_rules` | 连续工作、工时、休息间隔规则 | 默认规则供校验使用 |
| `scheduling_cycles` | 排班周期 | 一个周期可包含多个计划 |
| `schedule_plans` | 部门班表与版本状态 | 关联周期、创建人、人事审核人 |
| `schedule_assignments` | 某员工某日期的班次分配 | 关联计划、员工和班次 |
| `schedule_requests` | 调班、请假等特殊申请 | 关联原排班记录并记录审批状态 |
| `schedule_plan_versions` | 已提交班表的快照 | 关联 `schedule_plans` |

## 协作与审计

| 表 | 用途 |
| --- | --- |
| `notifications` | 面向员工的站内通知和已读状态 |
| `audit_logs` | 请求级审计日志，保留操作者、路径、状态码和请求 ID |

## AI 助手

| 表 | 用途 |
| --- | --- |
| `ai_usage_logs` | AI 请求限流计数 |
| `ai_conversations` | 会话元数据、记忆模式、摘要和会话事实 |
| `ai_conversation_messages` | 每轮用户与助手的已保存消息 |

## 数据一致性原则

1. 单条写操作统一通过 `utils/mysql_storage.execute` 执行。
2. 跨表状态流转，例如审批和排班变更，使用显式事务与行锁。
3. 外键保证员工、任务、排班等核心记录的引用完整性。
4. 结构变更通过 `backend/migrate.py` 执行，不依赖应用 worker 启动时并发迁移。
